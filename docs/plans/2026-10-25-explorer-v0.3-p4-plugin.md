## Rulings (mine unless marked)

- R1 Old builds keep InputSet: `Mark` already visits `input_set` as run metadata and keeps an unknown kind as itself. This build's Mark does not follow an InputSet's input addresses: a run does not own what it read.
- R2 Inputs not held are never `missing` rows (accepted by the P4 lead). Presence is a join of `run_input.address` against `block` or a snapshot presence check.
- R3 `Input.sample` is the `meta.id` of the tuple that holds the file; separate `path` inputs get null. Role precedence: `samplesheet` (params.input) > `param:<name>` (base name equals a file-valued param's base name) > `task`.
- R4 Foreign files Nextflow staged into `work/stage-*` are hashed from that local copy. A file only reachable remotely gets `reason: "remote"`, except `params.input`, read remotely up to 16 MiB.
- R5 Handoff: the block's `params` go through the `Leaks` scrub; the response's are unscrubbed and never stored (accepted). The Handoff roots its files (content) and keeps its Selection whole (it is the citation); its `project` link is not followed.
- R6 A Project is rooted like a Selection: kept until a current `delete` Claim, itself only.
- R7 No schema version bump. Migration: when a cache gains the P4 tables, or seeds from a snapshot without them, each member is read once in full for `project`/`handoff` entries and its RunCompletions with a non-null `input_set` are read again for `run_input`. Kept in one place (`Index.p4Rescan`) so it can move onto P3's general hook (orchestrator, via the P4 lead) when that merges.
- R8 (orchestrator, via the P4 lead) This build's sweep refuses to apply when a member's Store Log holds an entry kind it doesn't know. A dry run works and lists the unknown kinds; a real sweep exits non-zero and says to upgrade.
- R9 (P4 lead) A project's default-store policy never overrides a member's readOnly. Same-sample, sample and annotation Claims hang off the Project. The `CopyClosure.categoryOf` edit is approved; keep it small.
