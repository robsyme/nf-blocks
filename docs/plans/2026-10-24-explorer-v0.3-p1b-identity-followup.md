# Explorer v0.3 P1b follow-up: lazy identity, claim history, stdout hygiene. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Only commands that sign pay for resolving an identity. The Selection rail keeps claim history. Every nf-blocks notice goes to a channel the person can see without dirtying a command's stdout.

**Architecture:** `CasSession` resolves its `Principal` lazily, memoised on first use. `Put` and `Sweep` take a supplier, so building them resolves nothing. `CasSession` gets one notice channel. A run's session (and the run path of `CasSession.of`) uses the `nextflow.cas` console logger. A command session (`forCommand`) uses the command's own `err` stream. Identity lines, the storage-class warning and clock-skew warnings all go through it. The page's rail renders superseded claims muted.

**Tech Stack:** Groovy 4 plugin (Spock, `make test`); vanilla ES modules in `web/` (node:test).

**Spec:** the orchestrator's follow-up list (copied verbatim into the tasks below), on top of `docs/design/03-agent-prompts.md` P1b and `docs/design/mockups/08-selection.html` ("Rename writes a new name claim that supersedes the old one; the Claims list keeps history"). The previous plan is `docs/plans/2026-10-24-explorer-v0.3-p1b-identity.md`, and `docs/identity.md` is the current resolution doc.

## Global Constraints

- Leave the order alone (explicit `cas.asserted_by`, then Platform, `NXF_BLOCKS_USER`, git, anonymous), and leave email-on-hover alone. Both are waiting on the user.
- Don't change the block, log or index schema (v3). No `data-*` hook the Gate reads may move: `data-name`, `data-claim` on the header name tag and on pin and deletion rows, `data-pin`, `data-unpin`, `data-badge`, `data-retention*`, `#rename-*`, `#pin*`, `#release`, `#restore`.
- Tests never call a real Seqera Platform and never resolve the developer's git email.
- Principal comparison, everywhere: trim ASCII whitespace (space, `\t`, `\n`, `\r`, `\f`, `\v`) and lowercase ASCII letters only. SQL: `lower(trim(x, char(32,9,10,13,12,11)))`. JS: the same set and ASCII-only lowercasing. `docs/identity.md` says exactly this.
- Commit with `git add <paths>`. Messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Prose follows `~/.claude/CLAUDE.md`.
- Never `make install`, never write into `~/.nextflow`, never push.

## Review Focus

1. `nextflow plugin nf-blocks:items …` (read-only) with `TOWER_ACCESS_TOKEN` set and Platform unreachable must not wait, spawn git or warn. Task 1 tests that a command session that never signs never calls any seam.
2. `nf-blocks:explore` must listen before identity resolves. The page's members.json waits for the identity, bounded by the resolver's own timeouts. Task 1 tests that the server answers `/` while resolution is still blocked.
3. Two threads writing at once from explore resolve once. Task 1 tests memoisation under concurrent first use.
4. `sweep --format json` and `items --format json` stdout stays one JSON object, even with a clock-skew warning or a storage-class warning due. Task 1 tests each notice on a command session landing in the injected `err`.
5. On macOS without the Command Line Tools, nothing runs `/usr/bin/git`. Task 1 tests the guard with an injected os name and an `xcode-select` runner.

### Task 1 (plugin): lazy identity, one notice channel, guards

Owns: `src/main/groovy/robsyme/cas/{CasSession,Identity,PlatformIdentity}.groovy`, `core/Put.groovy` (the assertedBy parameter only), `core/Sweep.groovy` (likewise), `cli/*.groovy` and `explore/{ExploreCommand,ExploreServer}.groovy` (session and err wiring only), `build.gradle` (remove the Test env block), a new Spock global extension under `src/test/groovy/robsyme/cas/` plus its `META-INF/services` file, the affected tests, `docs/identity.md` and `DESIGN.md` (§2 and §16).

Items from the orchestrator, verbatim:
- S1. Identity resolves eagerly in the CasSession constructor (CasSession.groovy:200-203), so every CLI verb pays for it, read-only ones included (items, snapshot, reindex, dry-run prune/sweep). Each call spawns git and prints an anonymous warning that talks about 'this run's blocks'. With TOWER_ACCESS_TOKEN set and Platform unreachable, each call waits up to 5 s; explore took 7 s to listen. Resolve lazily on first use of assertedBy, so only verbs that sign (put, sweep --apply, prune --apply, claim writes from explore) resolve. Print the 'signing as X (from Y)' line to stderr for those verbs. nextflow plugin writes no .nextflow.log, so today a CLI put signs with the git email silently.
- Put the TOWER_* guard in a shared Spock fixture that defaults platformIdentity to a refusing double, so IDE test runners never call api.cloud.seqera.io and no test resolves the developer's git email.
- After a Platform failure, the anonymous warning still says 'no identity is configured' (Identity.groovy:107). Make it say what failed.
- DESIGN.md §16 still says explore prints only the URL on stdout. Update it.
- Close the HttpClient for each Platform call, and close git's process streams.
- git can pop the Xcode install dialog on macOS without the Command Line Tools. Avoid that without adding a dependency (for example, check that xcode-select -p succeeds before calling /usr/bin/git on macOS). Note it in docs/identity.md.
- warnOnce's storage-class warning never reaches the console, and clock-skew warnings can land on stdout under --format json.

Decisions (controller rulings):
- `CasSession.principal` becomes `Principal getPrincipal()` and `assertedBy` becomes `String getAssertedBy()`, so existing `cas.assertedBy` callers compile unchanged. Both are memoised and thread-safe (resolve once).
- `Put` and `Sweep` take a `Supplier<String>` (or `Closure<String>`) in place of the String. `Put` calls it only when it builds a Selection or Claim. `Sweep` calls it only when `apply` writes a Forget. A dry run never calls it. Sweep keeps its `'nf-blocks'` fallback for a null or blank answer.
- A run session resolves at `onFlowBegin` as today, through first use. The console line goes through `nextflow.cas`, as now.
- The notice channel: `CasSession.forCommand(CasConfig config, PrintStream err)` keeps `err`. A command session's notices (identity warnings, the "signing as" line, storage-class, clock-skew) go to that `err`, once each. A run session's notices go to `ConsoleLog.LOG` (warn or info), once each. `warnOnce` and `checkClock` use the channel. Drop the old no-err `forCommand(config)` overload if nothing needs it.
- For a command session, the "signing as" line now prints to `err` when the verb signs, on first resolution. It no longer goes to debug.
- Explore uses a command session with its `err`. Its stdout stays the URL line only. It starts resolution on a background thread right after the server listens, prints the signing line (or the warning) to stderr when that thread finishes, and `/members.json` waits for that result. The resolver's own timeouts (Platform 5 s, git 2 s) are the only bound. `ExploreServer` takes a `Supplier<Principal>` (or a future) in place of the `Principal`.
- Warning text:
  - For a command session, the anonymous warning says `nf-blocks: no identity is configured, so what this command writes will say 'anonymous'. Set NXF_BLOCKS_USER or git config user.email (see docs/identity.md)`.
  - For a run it keeps "this run's blocks and claims".
  - After a Platform failure that leaves nothing else, print one warning in place of the two: `nf-blocks: could not read your Seqera Platform identity (<reason>) and no other identity is configured, so <what> will say 'anonymous'. Set NXF_BLOCKS_USER or git config user.email (see docs/identity.md)`. `<what>` is the run or command wording above.
  - A Platform failure that falls through to a real source keeps today's single "using <next> instead" warning.
- git guard: if `os.name` starts with `Mac` and the `git` that would run resolves to `/usr/bin/git`, run `xcode-select -p` first (2 s bound). A non-zero exit skips the git step and logs at debug. Make `os.name`, the PATH lookup and the `xcode-select` runner injectable for the test.
- Spock fixture: a global extension that installs a refusing `PlatformIdentity` (it throws `IOException('tests never call Platform')`), a fixed `GitEmail` returning null, and an `env` without `TOWER_*` or `NXF_BLOCKS_USER` before every spec. It restores them after. Specs that set their own seams keep working. Remove the `tasks.withType(Test)` env block from `build.gradle`.
- `docs/identity.md` must cover: lazy resolution (who resolves and when), where each line goes (run: console; command: stderr; explore: stderr, stdout is the URL), the macOS guard, the combined Platform-failure warning, and the comparison rule from the Global Constraints. DESIGN.md §16 must say explore's stdout is the URL line and identity notices go to stderr.

### Task 2 (web): claim history in the rail, comparison rule, copy

Owns: `web/src/views/selection.js` (railClaims and the `ctx.use` payload), `web/src/panel.js` (the rail Claims section), `web/src/identity.js`, `web/src/views/identity.js`, `web/src/queries.json` (the four `…By` predicates), `web/src/styles.js` (the `/* P1b identity */` block) and their tests.

Items from the orchestrator, verbatim:
- S2. The Selection rail's Claims list drops superseded claims (selection.js:112-113 uses claimState().current). Mockup 08's spec note says the Claims list keeps history. Show superseded claims muted, with who/when.
- The #/identity note should say NXF_BLOCKS_USER also applies when the Platform read fails.
- SQL trim() strips spaces only, but JS trim() strips all whitespace. Make both sides compare the same way.
- Remove the unused isMine export.

Decisions:
- The rail's Claims section lists the current name claims first, then every superseded claim the Selection has (any attribute, so renames and undone deletes show), newest timestamp first. Current pins and the current deletion stay in their own panels, as now.
- Each superseded row is the normal claim tag, with avatar, verb, value and relative age. It gets a muted style (a `.claim.old` rule in the P1b CSS block: reduced opacity, ink-3 text) and a `title` reading "Superseded". Rows carry `data-rail-claim` and `data-superseded` on old ones, never `data-claim`.
- The claims list comes from the subject's full claim list, which the model already returns (`claims` beside `claimState`'s fields). Supersession is `claimState`'s rule, which a claim's cid listed in another's `supersedes` shows.
- Comparison rule: see the Global Constraints. `samePrincipal` and the four `…By` queries change together.
- The #/identity closing note adds that `NXF_BLOCKS_USER` also applies when a Platform token is set but the Platform read fails.
