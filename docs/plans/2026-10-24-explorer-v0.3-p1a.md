# Explorer v0.3 P1a (run Samples tab, cross-output join) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Samples tab to the run page (default when the run's items share a join key) that joins every output's items on `meta.id`, filters samples across outputs, and hands the filtered samples off as picks, a Selection or a snippet. Add search v1, and fix the P0 follow-ups on the items grid.

**Architecture:** Everything is built from item blocks in the browser, the way the items grid works today: no index schema change. A pure module (`samples.js`) turns per-output item previews into a sample table, evaluates output-qualified filters and computes hand-off sets. The view (`views/samples.js`) loads the run's items and draws the tab; the right rail gets a hand-off state in `panel.js`. Search v1 adds page queries that use existing indexes only (`item_attr(path,type,value)` and primary keys).

**Tech Stack:** ES modules, esbuild, node:test with `web/test/dom.mjs`, sqlite-wasm over HTTP range, Spock (`ExplorerQueriesTest`) for page query plans, Playwright from the main checkout's `gate/browser/node_modules` (screenshots only).

**Spec:** `docs/design/03-agent-prompts.md` (preamble + "P1a"), `docs/design/02-design-doc.md` §5, `docs/design/mockups/src/pages/07-run-samples.html` and `12-search.html` (their META spec notes are spec; 07 is interactive, and its threshold, tick and snippet behaviour is the spec), the P1a addendum (below), `docs/design/reports/p0.md` (what P0 built and its rulings).

## Global Constraints

- No index schema change, no block or log format change. New page queries go in `web/src/queries.json` and must pass `ExplorerQueriesTest` (no `SCAN` except `SCAN run USING COVERING INDEX`, `SCAN json_each`, `SCAN CONSTANT ROW`). Search on run names, file names, output names and Selection names is out of scope (search v2, after P2's schema bump).
- Build on the P0 kit: `kit-css.js` classes, `components.js` builders, `format.js` (`bytes`, `formatNumber`, `formatValue`, `sizeText`), `seal.js`. No restyling of shared components. New CSS goes only in a delimited block at the end of `web/src/styles.js`: `/* --- p1a task N: <name> --- */` … `/* --- end p1a task N --- */`.
- Keep every `data-*` attribute the Gate and web tests read (see the P0 plan's list). `cd web && npm test` stays green.
- Never show a CID as a label: runs by name, items by sample id, short CID only as secondary mono text. Numbers through `formatValue` / `formatNumber` (`99,566`, `89.0%`→`89%` per P0's ruling, floats 3 s.f.). Bytes through `bytes`.
- URL `where` on the Samples tab: a JSON list of `[key, type, value]` or `[key, type, value, op]`, op one of `!= > >= < <=`; `key` is `output:path` (qualified) or `path` (any output). Example: `#/run/<cid>?tab=samples&where=[["preprocessed:num_trimmed_reads","int","50000",">="]]`.
- The plugin DSL does not change. The cross-output snippet is a proposal, labelled as one on screen, with an ADR.
- UI copy, docs and commit messages follow `~/.claude/CLAUDE.md` (no em-dash runs, no "not X, it's Y", no bold-first bullets, plain words). Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Real data: roblab at `/tmp/cas-exploration/store` (runs `distraught_murdock`, `sad_yonath`, `sharp_magritte`, nf-core/rnaseq; `sleepy_heyrovsky`, main.nf).

## Rulings this plan makes (lead)

- Labels (addendum): the rnaseq promoted fields are `preprocessed:num_trimmed_reads` "Reads (trimmed)" (int), `aligned:percent_mapped` "% mapped" (percent), `meta.single_end` "Layout" (true is single, false is paired) and `meta.strandedness` "Strand", the source of mockup 07's "Strand" header. The plan first named `meta.salmon_strand_analysis.inferred_strandedness` from the spec's list; the lead overruled that after the roblab check, where the inferred path exists on 1 of 5 samples (WT_REP1). The inferred path is an ordinary field (on the Samples tab, in the column picker). The item, items and Selection pages read "Strand" too.
- The join key is per pipeline, default `['meta.id', 'id']`: an item's key is the first of these paths it has as a string. (lint_* outputs carry only `id`.)
- Samples and run-level outputs: the run's samples are the key values of items in outputs that hold two or more items. An output is per-sample when every item's key is a sample; otherwise it is run-level (roblab: quant_merged, quant_merged_pseudo, deseq2, deseq2_pseudo, multiqc, pipeline_info). With no multi-item output, the run has no samples and no Samples tab.
- The merged note comes from evidence. A run-level output's note counts samples only when the pipeline config names a matrix file and its header row, read through the file preview, lists sample ids as columns: "Holds 5 samples as columns; your 2 are among them. Preview". Otherwise the note reads "One item for the whole run." The page never claims coverage it cannot see.
- Promoted columns on the Samples tab never move to a strip: they are always columns, constant or not.
- The hand-off rail's actions are "Pick N items" (adds the ticked outputs' items to the tray, so `#/compose` and the existing save work) and "Save as Selection" (saves the same members directly, then names it).
- Column stability (addendum S1): once a promoted column has been shown for an output in this page session, it stays a column; a filtered view never moves a promoted field to the strip; only an unfiltered view with no memory of it may.

## Review Focus

1. Outputs whose items carry the key at different paths (`id` only in lint_*), carry a non-sample key (`all_samples`, `multiqc_report`) or none (pipeline_info): the join must not invent samples or drop per-sample outputs. Test in Task 1 (`buildSamples` on a roblab-shaped fixture).
2. A qualified filter on an output where a sample has no item: `=` and ranges fail that sample, `!=` passes it, matching `Index.items` semantics. Test in Task 1.
3. Manual tick, then a filter change: manual overrides clear (mockup behaviour), and the Selection records the final ticked list. Test in Task 2.
4. A run with no join (main.nf `sleepy_heyrovsky`, or only single-item outputs): Outputs stays the default; `?tab=samples` shows a plain empty state with a link to Outputs, never an empty table. Test in Task 2.
5. Search text with `%`, `_`, quotes or unicode, and short `baf` prefixes: ranges, not LIKE, so nothing is a wildcard; an address jump needs at least 6 characters after `b` and exactly one match. Test in Task 4.
