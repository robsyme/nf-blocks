# Explorer v0.3 P2: storage accounting, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-store storage accounting, computed when the snapshot is written: stored, referenced, dedup, pinned/held/releasing, per run, per person and per file kind. A Storage view and bytes-before-commit on Release, Pin and Unpin. Index-backed sizes replace P0's client-side block walks.

**Architecture:** The cache index learns content edges at ingest time: `block(cid, size, codec)` and `block_ref(owner_cid, cid, name)`, covering Leaf references from items and entries from DirectoryManifests. `IndexSnapshot.build` derives roots from the member's runs, Selections and pin Claims. A pure Groovy class (`StorageStats`) then computes reachability and writes the aggregate tables into the snapshot. The page reads those aggregates with one small query per figure. A v3 snapshot still opens, and its sizes fall back to P0's walks.

**Tech stack:** Groovy 4 + Spock (plugin, index), SQLite (xerial JDBC; sqlite-wasm in the page), vanilla JS ES modules with `node --test` (web), Python 3 unittest (gate).

**Spec:** `docs/design/03-agent-prompts.md` (preamble + P2), `docs/design/02-design-doc.md` §3, mockups `docs/design/mockups/09-storage.html` and `10-run-storage.html` (top comments and Spec notes are spec). The addendum's items are folded in below. P0 report: `docs/design/reports/p0.md`.

## Rulings (documented in the report)

- **R1 Stored.** Stored is the unique raw file blocks reachable from the member's logged runs and Selections, with sizes taken from Leaf and DirectoryManifest entry records. The 13 roblab blocks (7,901,789 B) that only the coordinate tree names (`pipeline_info/*`) are left out. No record references them, a sweep reclaims them (DESIGN.md: coordinates are "not blocks, not roots"), and listing every block at every snapshot write isn't viable on S3. On disk, roblab holds 150,035,889 B of raw blocks.
- **R2 Referenced.** Referenced is the sum, over every (output collection, item) membership of the member's runs, of every raw file reference under that item, with directories expanded. That is what the runs would occupy if each kept its own copies. Selections point at items and add nothing.
- **R3 Roots.** Roots follow `Mark`'s rules.
  - A run is `held`, or `released` (one clean `set retain "lineage"`), or `deleted` (hidden).
  - A Selection is `held` or `deleted`.
  - Every current `add pin` Claim gives one `pin` root per (subject, asserter), with state `pinned`.
  - Content roots are `held` and `pinned` roots.
  - The store partition is: Pinned = reachable from any pin root. Held = reachable from a held root and not pinned. Releasing = everything else stored, which is reachable only from released or deleted roots. Pinned + Held + Releasing = Stored.
- **R4 Freed on release** for a root is its `exclusive_bytes`: bytes in its closure reached by no other content root. Unpin shows the pin root's `exclusive_bytes` ("kept only by this pin").
- **R5 Pipeline size (addendum).** A pipeline's Stored counts runs that hold content here: held runs, plus released or deleted runs whose cid is pinned. Delete-hidden runs are excluded, matching the run list. Released runs' files are shown as "releasing", because a sweep reclaims them. This reverses P0's ruling that counted delete-hidden runs.
- **R6 Released run (addendum).** A released run's page says it *references* N, and that M of it is releasing (its `exclusive_bytes`), with the earliest deletion date. It no longer reads as plain "referenced".
- **R7 Grace.** The snapshot's meta carries `sweep_grace_ms`, from `cas.sweep.grace` (default 14d), when the writer knows it. The earliest deletion date is the release time plus the grace. With no key, the copy says "after the sweep's grace period" with no date. We never promise a sweep date: sweeps are run by hand.
- **R8 Cross-store.** Stats count blocks reachable from roots logged in this member. A Selection here that points at another member's items counts those blocks here. That is a known limitation, and presence ("Missing here") belongs to P3.
- **R9 Single store.** With one store open, the card row is hidden. The store's summary (numbers, bar, Yours) heads the breakdown, as the mockup's empty-state note says.

## Review focus

1. A Leaf whose `size` is null, but whose address is present. Use `store.size(cid)` when the block is present. Otherwise the size is NULL, and the stats count it as 0 and set `partial` (T1 and T2 tests).
2. A DirectoryManifest that hasn't arrived, or that holds a nested directory or a cycle. A `missing(item, manifest)` row is written, recursion uses a visited set, and ingest never loops (T1 test).
3. A subject pinned twice by the same asserter, and also by two asserters. Exclusivity is per (subject, asserter) root, so each pin's Unpin shows 0 B when someone else also pins it (T2 test).
4. A stale tail run (newer than the snapshot) on the Storage tab and the home page. Its sizes use P0's walk, and Release on it says "figures as of the next snapshot" with no freed number (T5 test).
5. A v3 snapshot: the page opens, `#/storage` says the snapshot predates storage figures and names `nextflow plugin nf-blocks:snapshot`, and the sizes use the walks (T5 test).

```sql
CREATE INDEX block_ref_owner ON block_ref(owner_cid)

CREATE TABLE root_stats(root_id INTEGER PRIMARY KEY, reachable_bytes INTEGER, reachable_blocks INTEGER,

CREATE TABLE root_shared(root_id INTEGER, other_root_id INTEGER, bytes INTEGER)
CREATE INDEX root_shared_root ON root_shared(root_id)
CREATE TABLE store_stats(stored_bytes INTEGER, stored_blocks INTEGER, referenced_bytes INTEGER,

CREATE TABLE asserter_stats(asserted_by TEXT PRIMARY KEY, reachable_bytes INTEGER, exclusive_bytes INTEGER,

CREATE TABLE pipeline_stats(pipeline TEXT PRIMARY KEY, runs INTEGER, bytes INTEGER, blocks INTEGER, releasing_bytes INTEGER)
CREATE TABLE collection_size(collection_cid TEXT PRIMARY KEY, bytes INTEGER, blocks INTEGER)
CREATE TABLE item_size(item_cid TEXT PRIMARY KEY, bytes INTEGER, blocks INTEGER)
CREATE TABLE kind_stats(kind TEXT PRIMARY KEY, files INTEGER, bytes INTEGER)
CREATE TABLE pinned_overlap(subject_cid TEXT, asserted_by TEXT, bytes INTEGER)
CREATE INDEX pinned_overlap_subject ON pinned_overlap(subject_cid)
```
- The cache index fills `block` and `block_ref` only. Every other new table is filled by the snapshot build (T3) and stays empty in the cache.
- `block_ref` owners are OutputItem cids (one row per addressed Leaf, `name` = Leaf name) and DirectoryManifest cids (one row per entry with an address, `name` = entry name). Rows are facts about immutable blocks: write an owner's rows once (skip when the owner already has rows), and never delete them in `clearRun`.
- `block` rows: a raw cid's `size` comes from the Leaf or entry `size`; when that is null and the block is present, it comes from `store.size(cid)`; otherwise it is NULL. A DirectoryManifest's row has `codec 'dag-cbor'` and the size of its encoded block. Use `INSERT OR IGNORE`; the first size wins.

**Interfaces (produces, used by T3):**
```groovy
@CompileStatic final class StorageStats {
  @Canonical static class Root { int id; String cid; String kind; String assertedBy; String state; String since
                                 String pipeline /* runs only, else null */; List<String> seeds /* item cids, or raw/manifest cids for a pin on a file */ }
  static StorageStats compute(Map<String, Long> rawSizes,                 // every raw cid with its size (null size allowed)
                              Map<String, List<String>> refs,             // owner -> referenced cids, multiplicity kept (block_ref)
                              Map<String, List<String>> names,            // raw cid -> names it is referenced by
                              List<Root> roots,
                              Map<String, List<String>> collectionItems,  // output collection cid -> item cids (multiplicity kept), for Referenced and collection_size
                              Set<String> manifests)                      // dag-cbor owners in refs
  // Results, each one row-shaped for the T1 tables:
  Map store; List<Map> rootStats; List<Map> rootShared; List<Map> asserters; List<Map> pipelines
  List<Map> collectionSizes; List<Map> itemSizes; List<Map> kinds; List<Map> pinnedOverlap
}
```
- A root's closure is the raw cids reachable from its `seeds` through `refs` (manifests recurse, with a visited set). T3 expands each seed list:
  - run: the items of its output collections
  - Selection: its items, recursively through child Selections
  - pin: on a run, as the run; on a Selection, as the Selection; on a collection, its items; on an item, the item; on a raw or manifest cid, itself
- An asserter key is `assertedBy.trim().toLowerCase()`, with null read as `anonymous`.
- Field rules follow rulings R1 to R5:
  - store: `stored_*` is the union of every root's closure (all states).
  - store: `referenced_bytes` = Σ over collectionItems of the raw refs under each item, with multiplicity.
  - store: `shared_bytes` = stored blocks reached by ≥ 2 **run** roots.
  - store: `partial` = 1 when any reachable raw size is null.
  - `root_shared`: per content root, the top 5 other content roots by overlapping bytes, ties broken by other cid.
  - `pinned_overlap`: one row per (subject, pinning asserter) with bytes > 0, for each run, Selection, item and pinned raw cid.
  - `kind` is the extension (same rule as `web/src/sizes.js` `extOf`, lower case, '' when none) of the lexicographically smallest name a block is referenced by.
  - pipelines: R5.
