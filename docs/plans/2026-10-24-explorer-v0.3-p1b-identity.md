# Explorer v0.3 P1b: identity. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `asserted_by` becomes a real principal, resolved once per session, and the explorer shows who and when on every claim and Selection, with a "Mine" filter on runs and Selections.

**Architecture:** The plugin resolves a `Principal(name, source)` when a `CasSession` is built. Each step of the resolution goes through a seam (env map, git runner, Platform client), so tests can swap any of them. The resolved name is what every block's `asserted_by` already carries, so block and log formats don't change. `nf-blocks:explore` adds `identity: {principal, source}` to `members.json`, and the page reads it to know "me". "Mine" is a query-level filter on `run.asserted_by` and `collection.asserted_by`, which already exist in index v3, so the schema doesn't change.

**Tech Stack:** Groovy 4 plugin (Spock tests, `make test`); vanilla ES modules in `web/src` (node:test, `cd web && npm test`), built by `web/build.mjs`.

**Spec:** `docs/design/03-agent-prompts.md` (preamble + "P1b: identity"), the P1b addendum (copied into Task 4 and Task 6 below), `docs/design/02-design-doc.md` §1 and "Identity", mockups `docs/design/mockups/01-components.html` (Claim tag and Avatar rows, anonymous state) and `08-selection.html` (header claim tag, Claims rail). The kit is in `web/src/components.js`, `kit-css.js` and `format.js`; see `docs/design/reports/p0.md`.

## Global Constraints

- Resolution order, settled with the orchestrator: explicit `cas.asserted_by` config, then Seqera Platform identity (if a token is configured), then `NXF_BLOCKS_USER`, then `git config user.email`, then `anonymous` with a visible warning. An explicit setting overrides a verified Platform identity. The doc must say so.
- Don't record the resolution source in any block. Only `asserted_by` (the principal's name) goes into blocks. The source goes to `members.json` and the console only.
- Index schema stays at v3; P2 owns this wave's bump. Query additions get tests.
- Keep every existing `id` and `data-*` hook (`data-badge`, `data-claim`, `data-pin`, `data-name`, `data-retention*`, …). The Gate reads them.
- Every claim shows who and when: avatar (initials, principal on hover via `title`, and the accessible name) plus age. The anonymous avatar is the kit's dashed `?` and links to `#/identity`.
- UI copy, docs and commit messages follow `~/.claude/CLAUDE.md` (no em-dash runs, no "not X, it's Y", no bold-first bullets, straight quotes).
- Don't reformat shared files. Keep edits scoped. Commit only the files your task owns (`git add <paths>`, never `git add -A`), because tasks may run at the same time in this worktree.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never `make install`, never write into `~/.nextflow`, never push.

## Review Focus

1. Platform endpoint slow, down or answering 401: a run must not hang or fail. Expect a bounded wait (5 s connect+read), one warning naming the fallback, then the next source. Task 1 tests a timeout and a 401 through the client double.
2. `git` missing from PATH, or `user.email` unset or blank: fall through without a stack trace. Task 1 tests a runner that throws `IOException` and one that returns `""`.
3. Case and whitespace: `Ada.Lovelace@Example.org ` in a claim and `ada.lovelace@example.org` from git are the same person for "Mine" (trimmed, case-insensitive). Task 5 tests this in both the SQL and the tail filter. Task 3 tests it in `isMine`.
4. A page opened without `nf-blocks:explore` (`?store=…`, a static server), or an old server with no `identity` in members.json: claims still render, the Mine toggle is absent, and nothing throws. Tasks 3 and 5 test it.
5. Anonymous identity: Mine is disabled with a reason (it would otherwise match every anonymous row), and the top bar warns and links to `#/identity`. Tasks 3 and 5 test it.

**Interfaces:**
- Produces:
  - `@Canonical class Principal { String name; String source }`, nested in `Identity` or top level in `Identity.groovy`. `source` is one of `'config' | 'platform' | 'env' | 'git' | 'anonymous'`. `boolean isAnonymous()`.
  - `static Principal Identity.resolve(String configured, Map sessionConfig, Map<String,String> env, GitEmail git, PlatformIdentity platform, Closure<Void> warn)`
  - `interface GitEmail { String userEmail() throws IOException }` with a default `ProcessGitEmail` that runs `git config --get user.email` and waits at most 2 s. A non-zero exit gives `null`.
  - `interface PlatformIdentity { String email(String endpoint, String token) throws IOException }` with `HttpPlatformIdentity`: `GET <endpoint>/user-info`, `Authorization: Bearer <token>`, 5 s connect and read timeouts, JSON `user.email`. A non-2xx answer throws `IOException("HTTP <code>")`.

  - `static PlatformIdentity CasSession.platformIdentity` and `static GitEmail CasSession.gitEmail`, test seams like the existing `s3OpsFactory`.
  - `CasConfig.assertedBy` becomes the explicit configured value or `null`. `DEFAULT_ASSERTED_BY` stays `'anonymous'` and becomes the last fallback.

Resolution rules:
- Platform token: `sessionConfig.tower.accessToken`, else env `TOWER_ACCESS_TOKEN`. Endpoint: `sessionConfig.tower.endpoint`, else env `TOWER_API_ENDPOINT`, else `https://api.cloud.seqera.io`. Strip a trailing `/`.
- Blank strings (after trim) count as unset at every step. The principal is trimmed. It is not lowercased, so blocks keep what the user typed.
- Failure of the Platform step warns once, then falls through: `nf-blocks: could not read your Seqera Platform identity (<reason>); using <next source> instead`.
- Anonymous warns once: `nf-blocks: no identity is configured, so this run's blocks and claims will say 'anonymous'. Set NXF_BLOCKS_USER or git config user.email (see docs/identity.md)`.
- The token never appears in any message, log line or exception text.
- `CasSession` resolves in both constructors, through `warnOnce`. The test-seam constructor uses the static seams too, so existing tests that set `cas.asserted_by` keep their value.
