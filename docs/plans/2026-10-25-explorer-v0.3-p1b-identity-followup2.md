## Review Focus
1. A Selection deleted, then undone, then deleted again. The rail must show the current delete's reversal history in order, with no orphan rows.
2. `sweep --apply` against a store with nothing past deadline must still not resolve identity. Resolving early must not make an empty apply pay for it.
3. A put that fails store-level validation (wrong kind, clock skew, missing content) must not resolve identity or print "signing as".

### Task 1 (web): reversing claims in the rail

Integrator, verbatim: "An undone deletion or pin leaves the reversing claim nowhere. railClaims (web/src/views/selection.js:177) drops current claims with attribute null (deletion) or 'pin', so the rail shows a superseded "deleted"/"pinned" row with no who/when for the reversal. Release then restore does show "restored". Keep current del claims for the deletion and pin groups. Update pages.test.mjs ('a delete then undo...', 'a pin then unpin...')."

Decision: in `railClaims` (selection.js:218), the current rows keep every current claim except a current deletion-group `delete` (the page's deleted banner shows it) and a current pin-group `add` (the Pins panel shows it). A current `del` in the deletion group reads "restored". A current `del` in the pin group reads "unpinned". Use the existing `claimVerb`. Update the doc comment above `railClaims` to match.

### Task 2 (plugin): sign at the right moment, honest docs, steadier tests

Integrator, verbatim:
- "An applied sweep resolves identity mid-run, after the first batch is deleted, under sweep.lock (up to 7-9 s, notices mid-output). Resolve before the first delete."
- "Store-level put validation (kind, clock, missing content) runs after the signer supplier is called. Move it before if cheap, or fix the claim in docs."
- "docs/identity.md says explore's page doesn't wait for identity; it does (store.js boots after members.json, a 7-9 s blank UI with Platform down). Fix the doc, or render the shell before identity arrives."
- "IdentitySeamsExtension restores the real seams between specs; a leftover nf-blocks-identity daemon thread from ExploreCommandTest could resolve against them. Join or stub it."
- "Identity.onPath doesn't toRealPath, so a symlink to /usr/bin/git skips the xcode-select guard."
- "ItemsCommandTest's millis < 1000 may flake on slow CI. Loosen it, or measure connections and spawns instead."
- "CasSessionTest uses a real personal email as a fixture. Replace it with example.org."

Decisions:
- Sweep: when the plan has something to delete, resolve `signer()` before taking `sweep.lock` and before the first delete. An apply with nothing past deadline writes no Forget and never resolves.
- Put: move the store-level validation (kind, clock, missing content) ahead of the supplier call, so a rejected request never resolves. If one of those checks really needs the built block, say which in the commit message and keep it after.
- Explore's page: fix the doc (controller's ruling). The page waits for `/members.json`, so with Platform down the first load can take up to about 7 s (9 s on macOS with the git shim). Rendering the shell early would need a new endpoint and re-rendering every view when identity arrives, which this round's tight scope rules out.
- `docs/identity.md` also says plainly, near the top, that an explicit `cas.asserted_by` overrides a verified Platform identity.
- ExploreCommandTest: join (or await) the `nf-blocks-identity` thread before each spec ends. Expose the thread or future through a package-private accessor if needed. Stubbing alone isn't enough, because the thread outlives the spec.
- `Identity.onPath`: resolve the found git with `toRealPath()`. A link whose real path is `/usr/bin/git` counts as the shim. An unreadable link falls back to the path as found. Add a test with a temp-dir symlink.
- ItemsCommandTest: drop the wall-clock assertion. Assert the counting seams (zero Platform calls, zero git spawns) and an empty `err`.
- CasSessionTest: use `someone@example.org` in place of the personal address, everywhere in that file.
