# Explorer v0.3 P0 (polish pass) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the Blockprint mockup kit (tokens, app shell, components, Seal) into the explorer and land the ten P0 polish fixes from `docs/design/03-agent-prompts.md` without any index schema change.

**Architecture:** The explorer stays a vanilla-JS single page (`web/src`, `h()` DOM builder, esbuild bundle). The kit arrives as new modules (`kit-css.js`, `seal.js`, `format.js`, `components.js`, `promoted.js`) that every view composes. Sizes are computed in the browser from OutputItem Leaf sizes and DirectoryManifest entries (no `block` table until P2), cached on `Explorer`. Views are then restyled one file each.

**Tech Stack:** ES modules, esbuild 0.28, node:test with `web/test/dom.mjs` (fake DOM), sqlite-wasm over HTTP range, Playwright 1.63 (screenshots only).

**Spec:** `docs/design/03-agent-prompts.md` (shared preamble + "P0: polish pass"), `docs/design/01-ux-review.md`, `docs/design/02-design-doc.md` §1, §2, §6. Visual target: `docs/design/mockups/` pages 01, 02, 03, 04, 05, 06, 08. Each mockup's META block (in `docs/design/mockups/src/pages/*.html`) carries its spec notes and is part of the spec.

## Global Constraints

- Never show a filesystem path as an object's identity. Every claim shows who/when. Any action that keeps or frees data shows the bytes before commit (`Pin 5.29 MB in roblab`).
- No change to the index schema (`index/v3.sqlite`), block formats or log formats in P0.
- Keep every `data-*` attribute the Gate and the web tests read (`data-run`, `data-producer`, `data-item-result`, `data-pick`, `data-pick-all`, `data-via`, `data-kind`, `data-count`, `data-address`, `data-latest`, `data-error`, `data-block`, `data-block-check`, `data-snippet*`, `data-selection*`, `data-fold`, `data-panel-state`, `data-written`, `data-held-elsewhere`, `data-exists`, `data-member`, `data-where`, `data-name`, `data-command`, body `data-state/route/render`). `npm test` in `web/` stays green.
- Seal: port `docs/design/mockups/src/kit.js` `seal()` exactly: same CID gives the same SVG string.
- Bytes: kit `bytes()` formatting everywhere (SI, 1000-based; `<10` two decimals, `<100` one decimal, else none: `5.29 MB`, `21.1 MB`, `142 MB`, `417 KB`, `0 B`).
- Numbers: integers (and floats with an integral value, stored as `49791.0`) with thousands separators and no `.0` (`99,566`); other floats to 3 significant figures; a promoted field with `format: 'percent'` gets `%` (`89.6%`). Booleans use a promoted field's labels when it defines them.
- The Light/Dark/Spec-pins buttons and the dashed Spec notes panel are mockup chrome: never ship them.
- No external network fetches from the page (no Google Fonts): font stacks name Inter / JetBrains Mono first and fall back to system fonts.
- UI copy follows `~/.claude/CLAUDE.md` (no em-dash runs, no "not X, it's Y", plain words). Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Later phases build on the kit: P1a adds a Samples tab and extends `promoted.js`; P1b makes avatars real; P2 replaces client-side sizes with an index table; P3 adds presence for several stores. Keep those seams obvious (one function each), and do not build their features now.

## Review Focus

1. A Leaf whose address is a directory (DirectoryManifest), including nested directories and symlink/unresolvable entries: sizes must expand regular files recursively and count each raw CID once. Test in Task 2.
2. A Leaf with no address (`reason` set) or a block missing from this store: size code must skip it and say "size unknown" style partial totals, never throw or show `NaN`. Test in Task 2 (`partial: true`).
3. A float field whose value is integral (`"49791.0"`) next to a true float (`"89.62899137102112"`) and a string that looks numeric: formatting must give `49,791`, `89.6`, and the string unchanged. Test in Task 1 (`formatValue`).
4. Filters added or removed on the items grid: column order must not change, and `id` never leaves the first column. Test in Task 5.
5. An output whose items share no promoted fields, or a pipeline with no promoted config (`main.nf`): views fall back to varying fields A–Z and never render empty headers. Tests in Tasks 4 and 5.
