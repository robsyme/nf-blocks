Spec notes · P0 · polish · #/run/<completion_cid>?tab=outputs — not part of the UI

The run page with the Outputs tab open. The Samples tab (07) becomes the default once P1a ships; until then this is the default. The header carries the run's seal, status, durability, presence and stored size. The outputs table replaces the deep meta paths with promoted fields and replaces icon grids with labelled file-kind chips. Empty outputs collapse into one row.

Behaviour

  • Tabs: Samples · Outputs · Provenance · Storage. The tab is in the URL (?tab=).
  • Key fields: up to 3 promoted fields per output (pipeline-specific config, falling back to fields that vary across items, never meta.has_* booleans that are constant). Show '+N fields' as muted text.
  • File kinds: one chip per extension with a count, ordered by bytes desc, max 4 then '+N'.
  • Size column is right-aligned, with a mini bar scaled to the largest output.
  • '7 empty outputs' is a single collapsed row; expanding it lists the names inline.
  • Header 'Release…' opens the inline confirmation shown in 10-run-storage.html.
  • Provenance tab = 'Run details' today, restyled (params diff vs pipeline defaults, config collapsed). It must not render as blank table rows (bug in current build).

Acceptance

  • Sorting by Size works and is the default secondary sort after Items.
  • Clicking an output row opens 04-output-items.html for it.
  • The right rail snippet updates with 'this run' / 'latest good run' and untyped/typed, as today.
