## Format and config changes (flagged)

- **New block kind `Transfer`** (DESIGN.md §6): `{schema, asserted_by, roots, from, to, depth, claims, runs, blocks, copied, bytes, timestamp}`.
  - `asserted_by` is the copying principal. On the CLI that is P1b's resolution; on the explore server it is the server's own principal.
  - Copied Claims keep their own `asserted_by` and `timestamp`, because they travel as verbatim blocks.
  - `from` and `to` are member aliases. That is a stated exception to "nothing store-local", since the block is the provenance of one copy.
- **New Store Log kind `transfer`** (`<rts>-transfer-<cid>`). A copy writes every block first, then the ordinary `run-`/`selection-`/`claim-` entries it adds, then the Transfer block, then this entry last. A copy that writes nothing new writes no Transfer.
  - A build older than P3 ignores `transfer` entries, so its sweep would trash Transfer blocks. Mixed-version sweeps of a destination need P3 or later.
- **Index tables** `transfer(...)` and `transfer_root(transfer_cid, root_cid, role)`, created with `IF NOT EXISTS` in the cache and the snapshot. There is no schema version bump: the page checks `sqlite_master` and shows nothing on older snapshots.
- **Config**: `cas.stores.<alias>.readOnly`, for a member copy must never write.
- **`members.json`** gains `kind`, `location` (S3 only, never a local path), `copy_target` and `copy_reason` per member, and a top-level `copy`.
- **`POST /api/copy`** on the explore server (interface 1.7).
- **RunManifest scrub.** New runs' RunManifests are redacted more thoroughly, so they get a different address wherever a newly caught value appears. Existing blocks are unchanged. The scrub now covers:
  - credential shapes;
  - secret-named params values;
  - paths inside params strings and after `,` `;` `@` or glued short flags;
  - `~user`;
  - secret lists in config text.

  A user name directly after `@` (a GitHub handle) is kept.
- **Sweep retention across members (D2).** A sweep of member A releases or deletes a run or Selection that A's own Store Log lists only when A's own Claims and the whole composition's Claims agree. It keeps anything pinned in any member. Roots logged only in other members are judged as before P3. A sweep keeps at least as much as before P3 in every case. See DESIGN.md §19 and `CrossMemberReleaseTest`.

That is about 1,045 HEADs per plan on S3. The page's debounce and D10 bound how many run; a cheaper plan would need a request per depth.
- **Copy cost.** About two HEADs per closure block (the plan, then the re-ask after registering as a Live Writer), plus one PUT per block written and the entries, the Transfer and the snapshot.

## Deliberate differences from the mockups

- **Plan figures are real and larger:** 98 blocks / 1.35 MB, not 15 / 1.14 MB, because D7 carries the run's whole metadata (83 records). The chain row shows "run records 83 records".
- **"Already in org-local" is labelled "blocks"**, not "run records". It counts whatever is present.
- The "inputs · stay as references" chip shows only when the plan has unaddressed or missing references. Wigshop at results has none.
- **No per-group progress bar** (D6, synchronous endpoint).
- **"Copy, then release in roblab…" is shown only when the plan says kept.**
- The CLI command is the server's single line, which wraps; the mockup uses `\` continuations.
- The switcher popover is our design; the mockups only show the closed button.
- **Storage with several members:**
  - A card links to that member's Storage page, not to a `?store=` breakdown.
  - The head's lead line is dropped; the caption "Each store keeps its own pins and runs its own cleanup." carries it.
  - Cards other than the open member's don't state their snapshot's age.
- **All-stores Selections are paged per member**, so a Selection can repeat across pages; the pager says so.
- **An unreadable Transfer is traced on the Storage view**, because its roots can't be known.
- No Google Fonts (as in P0 to P2).

## Rulings

Each states what it costs if wrong. The plugin's own decisions are in its report.

- **D1 copy targets:** any configured member except the source, unless `readOnly` or an unwritable local directory. If wrong: a config option to remove.
- **D2 re-release, as narrowed:** see above. If wrong: A's "freed on release" can overstate when another member pins.
- **D3 pins off by default.** If wrong: one checkbox's default.
- **D4 presence:** the open member from the index; others by HEAD, only with several members. The item page also HEADs the open member for a partly swept item, because the index has no per-file presence. If wrong: one HEAD per file there.
- **Every configured member gets a dot**, filled or ring. If wrong: a ring overclaims "referenced" for a store that never saw the cid; the tooltip says "not in".
- **D5 all-stores:** lists merge every member; detail pages open in the holding member (`?member=`), and the switcher shows which. If wrong: readers may miss that a detail page is one store's view.
- **D6 synchronous copy endpoint.** If wrong: a long copy shows a spinner only.
- **D7 whole run metadata travels.** If wrong: a few hundred small records per run.
- **D8 the Transfer names its runs; `transfer_root.role`.** If wrong: one field.
- **D9 kept, not just present:** a copy that the destination's own Claims would release or delete is refused, and copy never writes a restore Claim. If wrong: one extra step (restore at the destination first).
- **D10 dry runs supersede:** at most one waits, and the older gets 409 `superseded`; the page debounces. If wrong: fewer stale plans answered.
- **Dry runs write nothing** at either store. **A copy that writes no block and no new entry writes no Transfer.**
- **Two cross-owner edits, approved:**
  - the plugin lead landed `web/test/fixtures/schema.sql` (transfer tables) and the one-line `schema.test.mjs` 24→25 type count;
  - the web fix probe fixed the same "null" bug in `views/items.js`.
- **An unreadable Transfer leaves a visible trace**, on the Storage view, never silence.
- **The all-stores Selections list dedups within a page only.**

## Open questions

- **Presence cost on S3, measured** (S3 section): after a Claim, about one extra HEAD per copied file (9 here); at every build, 367 HEADs re-asking recorded absences that a results copy leaves behind. Fix options: scope the memo drop to subjects the Claim can affect, and memoise absences under a transferred run until something writes them.
- **Nextflow's own lineage records hold local paths.** Scrubbed in the follow-up round, except `FileOutput.path` (see below).
- **Dry-run cost:** every plan checks the destination's `has` for the whole `all` closure (to fill all three depth cards). On S3 it also reads every FileOutput record of the run's `nf/` (1,734 for roblab). The page debounces, and D10 bounds the queue. A cheaper plan for `results` alone would need a second, narrower request.
- **Copy state in the page** lives in app memory. A full reload during a copy loses "a copy is running" (the server answers 409 `copy_running`), and the last result shows only on a copy page for the same root.
- **Selections have no release confirmation** with bytes (pre-P3). The copy page's release offer for a Selection links to Delete and shows the bytes freed in the source.
- **The scrub and audit** gaps listed here were closed in the follow-up round (see below and the plugin report).
- **Cross-process `Index.open` gaps**, `stop()`'s double grace, and an undecodable destination Claim failing plans with 500. See the plugin report.
- **Seqera Platform calls during acceptance.** Fixed in the follow-up round: `local-accept.sh` pins `cas.asserted_by` in every config, as `aws-accept.sh` does.
