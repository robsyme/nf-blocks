## What was built

**Kit port (the base later phases build on).** All new modules are in `web/src/`:
- `kit-css.js` holds the Blockprint tokens and component classes from `mockups/src/kit.css`, in light and dark. Dark applies under `prefers-color-scheme` (guarded by `:root:not([data-theme="light"])`) and under `:root[data-theme="dark"]`. Mockup chrome is dropped.
- `seal.js` is the Seal ported exactly from `kit.js`. A test runs the mockup's `kit.js` in `node:vm` and compares the SVG strings byte for byte.
- `format.js` has `bytes`, `formatNumber`, `formatValue` and `sizeText`.
- `components.js` has the builders: addrChip, factTag, claimTag, avatar with `toneFor`, presence, durability, status, kind/field/file chips, button, note, empty, pageHead, tabs, panel, kv, minibar, thread and storageBar.
- `storename.js` is the one place that decides the store name and colour key (`ctx.store.name`, `ctx.store.key`). P3 extends it.
- The app shell (top bar, left nav, rail) is rebuilt on the kit, and `#/kit` is a reference page of every component. It is not linked from the nav.

**Data seams.**
- `promoted.js` holds the per-pipeline promoted fields, starting with nf-core/rnaseq. P1a extends it.
- `sizes.js` and the `Explorer` methods `itemSize`, `collectionSize`, `runSize`, `pipelineSize` and `selectionSize` compute sizes in the browser from OutputItem Leaf sizes and DirectoryManifest entries. Each raw CID is counted once.
- These are block reads only, under one Explorer-wide limit. Work stops when the page that asked is gone.
- `itemBlock` is a block-only item read, used by previews, the Picked panel and compose.
- P2's index tables replace the size methods. Each scope has one method, and there is one display function, `sizeText`.

## Deliberate differences from the mockups
- These parts belong to later phases and were left out:
  - Samples tab and the cross-output hint on the items rail (P1a)
  - Avatars beyond rendering `asserted_by`: roblab's claims say `anonymous`, so they show the kit's anonymous state (P1b)
  - The store-wide "stored · referenced · dedup" line, Storage nav and Projects nav (P2, P4)
  - Copy to…, multi-store presence and "Missing here" (P3)
  - The Tidy samplesheet stored as a block (P4; today's CSV/JSON export stays)
  - The column picker: "N more fields:" buttons add columns instead
- No Google Fonts fetch: Inter and JetBrains Mono are used when installed, with system fonts as the fallback. Screenshots therefore differ in typeface.
- Release shows the bytes this run holds and says shared files stay. It does not show "frees N": that needs cross-root reachability, which is P2.
- Item page file groups are ordered by bytes, largest first. DAG-CBOR sorts map keys, so Nextflow's record order isn't stored. On roblab this gives the mockup's fastqc, trim, bbsplit.
- Constant promoted fields go to the "Same for every item" strip, as in the mockup. The rnaseq labels are "Strandedness" (`meta.strandedness`) and "Strand" (inferred). The Selection header and item chips read "Strandedness" where the mockup says "Strand".
- The run page rail's Provenance and Lineage content sits at the foot of the Provenance tab. There is no params diff against defaults.
- The file preview is a panel under Files, not a side sheet. HTML previews open on click in a sandboxed iframe without scripts.
- The kit demo's "% mapped" shows `89%`, not the mockup's `89.0%`: an integral float drops `.0` under rule 4.
- The rail's two toggles wrap onto two rows at the rail's width.

## Rulings made during the phase
Each ruling lists what it costs if it's wrong.
- Tasks 1 and 2 ran at the same time in this worktree, because their files were disjoint. Tasks 3 to 7 ran in parallel in isolated worktrees and the lead merged them; styles.js has one delimited block per task. If this was wrong, the cost is only the merge work, which is already done.
- No Google Fonts fetch, because the page is served from a local member and may run offline. If wrong, the typeface differs from the mockups.
- The later-phase parts of the P0 mockups were left out (see "Deliberate differences"). If wrong, those parts get built in their own phases anyway.
- pipelineSize counts runs hidden by a delete Claim, because their blocks are still stored. The Stored cell's title says so. If wrong, Stored overstates for pipelines with deleted runs until P2.
- "89%" rather than "89.0%" for an integral-float percent, following the number rule. If wrong, it is one visual difference.
- Item page file groups are ordered by bytes, largest first, because DAG-CBOR does not keep Nextflow's record order. If wrong, some pipelines get a different group order.
- pickButton labels ("Pick", "Pick this Selection", "Picked") were changed in common.js by its owner. No Gate code reads the text.
- One Gate step changed: B.retain now opens `?tab=storage`, because the Storage fold became a tab. Gate unit tests and tier B pass.
- Release shows held bytes and says shared files stay; it shows no "frees N" figure, because that number needs P2's reachability. If wrong, P0 lacks "bytes freed" at Release until P2.
- Constant promoted fields go to the "Same for every item" strip, reversing the plan, to fit Files and Size at 1440 as the mockup does. If wrong, a promoted column can move into the strip when a filter makes it constant.
- rnaseq labels: `meta.strandedness` reads "Strandedness" and inferred strandedness reads "Strand". If wrong, the run, item and Selection pages read "Strandedness" where the mockup says "Strand".
- The final re-review's one new bug, a stale-page size cache, got one scoped follow-up fix instead of being parked, because P2 builds on the size seam. It cost one extra commit, `6a86721`.

## Open questions and follow-ups
- Sizes are client-side and walk blocks. They are bounded: newest 10 runs per pipeline, an Explorer-wide limit, and work stops when the page is left. P2's `block` table should replace them through the existing size methods and `sizeText`.
- "Strandedness" vs "Strand" labels on the Selection and item pages: whoever owns promoted fields in P1a should settle it.
- Deferred minors are kept in the ledger and copied here:
  - claim ages use UTC, which P1b owns
  - a file's presence always shows "held", which P3 owns
  - home's Health is the latest run's line, not an aggregate
  - the Selection page calls `runLabel` per From collection, which the route's budget allows
